# DevShop 架构与维护约定

DevShop 沿用 SQLShop、LinkShop、RPShop 的 Rust 2024 / eframe 0.33 桌面结构和 Python 标准库打包契约，每个仓库可以独立构建。

## 模块边界

- `main.rs` 只声明桌面模块并调用 `app::run()`；`app.rs` 管窗口参数、启动图标、单实例生命周期。
- `lib.rs` 暴露 `json`、`jwt`、`storage`，业务模块不依赖 UI。
- `json` 使用原文和 40 字节节点索引，解析、搜索和格式化独立。键和值按需要解码，不将整棵文档转成字符串键的通用 DOM。
- `jwt` 分离解析、算法与密钥处理、签名验证、声明时间解释。解码不等于认证，算法必须显式选择。
- `storage` 分离原子文件写入与历史快照。历史文件名为内容哈希，索引不允许任意路径。
- `ui/mod.rs` 管生命周期和工作区组合；`actions.rs` 协调打开、保存和未保存确认；`background.rs` 管文件任务及单线程历史写入；`shell.rs` 管标题栏、工具栏、历史与确认窗口。
- `ui/theme.rs` 集中管理小熊猫暖橙主题的深浅配色、文字和卡片；`ui/welcome.rs` 提供空工作区入口和示例。
- `ui/window_chrome/resize/` 为 Windows 自绘窗口提供原生边缘命中检测，覆盖四边、四角和 DPI 缩放；最大化时关闭边缘缩放。历史列表使用固定高度的两行记录，保持虚拟滚动的行距一致。
- `branding.rs` 按实际显示尺寸与视口 DPI 缓存 logo 贴图；`branding_icon.rs` 通过预乘透明度过滤缩小图像，避免边缘黑色晕圈。标题栏、欢迎页、悬浮球和 Windows 图标共用同一原始图案。
- `ui/json_view/` 按异步操作、树行、原文、搜索和详情拆分。解析/搜索/格式化取消时保留当前输入，结果不会覆盖较新的任务。
- `ui/jwt_view.rs` 只保留当前会话的密钥。清空和示例通过 App 协调，不绕过未保存确认或沿用旧文件路径。
- `ui/floating.rs` 管独立透明置顶视口，通过消息队列向主窗口发动作；不直接写历史或修改文档。Windows 在 GL 表面建立后启用 DWM 透明度合成，保留圆边的抗锯齿像素；仅在合成不可用时退回原生窗口区域裁切。

## 文件和历史一致性

文件打开在后台读取，验证读取前后文件信息；保存写入同目录临时文件并同步，替换前再次核对预期文件信息。检测到外部修改时保留草稿并拒绝覆盖。文件元数据检查不能提供跨进程数据库式事务保证。

历史写入、收藏、删除和清理都进入单个 worker，避免索引的读改写竞争及快照清理竞争。退出时向队列追加停止命令并等待已有写入完成。内容按 SHA-256 去重，读取时复核哈希；损坏的索引会报错并保留原文件，不以空历史覆盖。

每个工作区保留自己的文件位置、来源和未保存状态。未应用的 JSON 节点编辑与未签名的 JWT 草稿也参与确认流程，不能以“当前 Token 未变化”为由静默丢弃。

## 打包和平台

Windows 使用自绘标题栏、统一任务栏/窗口图标和当前用户安装；macOS、Linux 使用平台窗口装饰。中文字体随应用内嵌并保留 OFL 许可。当前用户的首次安装是显式动作，后续固定启动器读最新完整版本路径，文件关联只注册 OpenWith。

脚本从 Cargo metadata 获取 crate 名、产品名、版本和目标平台。产物携带依赖许可、程序哈希和压缩包 SHA-256，拒绝覆盖同名包。CI 调用同一组脚本，不自行拼装另一套发布包。

## 维护检查

`scripts/check-structure.py` 检查自有代码文件边界，当前上限为 1,200 行或 128 KiB。新增职责应拆入所属模块，不能通过放宽上限持续堆叠。`dev.ps1 verify` 执行格式、严格 clippy 和默认测试；性能测量使用显式命令，不能把某台机器的结果当作所有文件和平台的保证。
